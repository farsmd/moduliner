# مودولاینر (Moduliner)

مینی‌فریم‌ورک PHP **ماژولار** بر پایه الگوی **HMVC** — سبک، **بدون هیچ وابستگی** (بدون Composer، بدون پکیج خارجی)، طراحی‌شده برای **هاست‌های اشتراکی** با دیتابیس **SQLite**.

فلسفه مودولاینر ساده است: **هسته فقط بارگذاری و یکپارچه‌سازی** می‌کند؛ تمام منطق کسب‌وکاری داخل **ماژول‌ها** زندگی می‌کند. اضافه، حذف یا جابه‌جایی یک قابلیت، یعنی اضافه، حذف یا جابه‌جایی یک پوشه — بدون دست‌کاری هسته.

## چرا مودولاینر؟

| نیاز | پاسخ مودولاینر |
|---|---|
| هاست اشتراکی بدون SSH/Composer | فقط PHP خالص؛ آپلود و اجرا |
| رشد تدریجی پروژه | هر قابلیت یک ماژول مستقل (Plug & Play) |
| پنل مدیریت آماده | ماژول admin با منوی داینامیک و مدیریت کاربران |
| سایت عمومی + پنل | ماژول pages برای صفحات سایت، جدا از پنل |
| به‌روزرسانی کم‌دردسر | ماژول update: آپدیت تک‌کلیکی از گیت‌هاب با بکاپ خودکار |
| مدیریت دیتابیس | ماژول database: بکاپ، بازگردانی، چند دیتابیس |

## نیازمندی‌ها

- PHP **۸٫۰** یا بالاتر (با افزونه‌های `pdo_sqlite` و `mbstring`)
- `mod_rewrite` (یا معادل آن) برای URLهای تمیز
- بدون نیاز به Composer، Node یا هر ابزار بیلد

## نصب

تنها مسیر نصب، **نصب‌کننده تک‌فایل** است (جزئی از سیستم نیست):

1. فقط فایل `install.php` را در هاست **خالی** آپلود کنید
2. در مرورگر باز کنید: `https://yoursite.com/install.php`
3. نصب‌کننده خودش **آخرین ریلیز** را از گیت‌هاب دانلود، استخراج و نصب می‌کند
4. حساب مدیر (owner) را با نام کاربری و رمز دلخواه بسازید
5. بعد از نصب موفق، `install.php` **خودش را حذف** می‌کند؛ اجرای مجدد روی سیستم نصب‌شده خطای **۴۰۳** می‌دهد

## معماری فنی

### چرخه یک درخواست

```
.htaccess → index.php → spl_autoload → App::run()
  → Router: اسکن modules/*/routes.php
  → تطبیق مسیر (اول دقیق، بعد داینامیک {param})
  → Modules\{name}\Controller::{method}()
  → Model (PDO + SQLite) → View (PHP خالص)
```

### هسته (`core/`) — کوچک و ثابت

| فایل | مسئولیت |
|---|---|
| `App.php` | بوت‌استرپ: سشن، اسکن ماژول‌ها، اجرای روتر |
| `Router.php` | ثبت و تطبیق مسیر؛ پشتیبانی از پارامتر داینامیک (`page/{slug}`)؛ نرمال‌سازی `/index.php` |
| `Controller.php` | کلاس پایه: `view()`، `redirect()` (مطلق با `BASE_URL` + تگ `<base>` برای ساب‌فولدر)، `notFound()`، `json()` |
| `Model.php` | کلاس پایه مدل‌ها: `query()`، `fetchAll()`، `fetchOne()` + متد انتزاعی `migrate()` |
| `Database.php` | سینگلتون PDO؛ فایل فعال از `database/active.txt` خوانده می‌شود (پیش‌فرض `app.sqlite`) |

**نکته معماری:** جدول هر ماژول با متد `migrate()` مدل خودش ساخته می‌شود — با اولین استفاده، خودکار و بدون اسکریپت جدا.

### آناتومی یک ماژول

```
modules/blog/
├── routes.php      ثبت مسیرها: $router->get('blog', 'blog', 'Controller', 'index');
├── Controller.php  namespace Modules\blog — منطق
├── Models/         namespace Modules\blog\Models — دسترسی دیتا + migrate()
├── views/          قالب‌های PHP خالص
└── menu.php        (اختیاری) آیتم پیش‌فرض منوی پنل
```

ماژول‌ها با **اسکن خودکار** شناسایی می‌شوند — برای فعال‌سازی، فقط پوشه را بیندازید داخل `modules/`.

### سیستم نقش‌ها (قابل‌توسعه از روز اول)

نقش‌ها رشته ساده‌اند (`owner` / `admin` / `user`) و در دیتابیس ذخیره می‌شوند — افزودن نقش جدید (مثلاً `editor`) نیاز به تغییر هسته ندارد:

```php
UserController::hasRole('admin'); // owner به همه‌چیز دسترسی دارد
```

- بعد از لاگین، `admin`/`owner` به `/admin` و کاربر عادی به `user/dashboard` می‌روند
- گارد `requireAdmin()` در کنترلرهای پنل: لاگین‌نبودن → ریدایرکت به لاگین؛ نقش ناکافی → **۴۰۳**

### منوی ماژولار پنل

هر ماژول با فایل اختیاری `menu.php` آیتم پیش‌فرض خودش را معرفی می‌کند:

```php
return [
    ['title' => 'وبلاگ', 'url' => 'blog', 'icon' => '<svg…>', 'roles' => ['owner', 'admin']],
];
```

- مدیریت نهایی (افزودن، ویرایش، حذف، **ترتیب**، فعال/غیرفعال، دسترسی نقش، انتخاب آیکون SVG) از پنل انجام می‌شود و در جدول `menu_items` ذخیره است
- در اولین اجرا، آیتم‌های `menu.php` ماژول‌ها **خودکار ایمپورت** می‌شوند؛ دکمه «همگام‌سازی از ماژول‌ها» فقط موارد **جدید** را اضافه می‌کند (بدون تکراری، بدون دست‌کاری تغییرات دستی)
- آیکون‌ها **SVG inline** هستند (ایموجی ممنوع) و هیچ فایلی از **CDN خارجی** لود نمی‌شود

### قالب‌های نمایش منو

رندر منو از منطق آن جداست؛ قالب‌ها در `modules/menu/views/templates/` زندگی می‌کنند:

- **`hamburger-right`** — منوی همبرگری کشویی از سمت راست (دکمه ثابت بالا-راست، دراور با اوورلی، بستن با ESC/کلیک بیرون/دکمه ×، قفل اسکرول بدنه). هم‌اکنون قالب پیش‌فرض **پنل مدیریت** است و در موبایل و دسکتاپ یکسان کار می‌کند.

## ماژول‌ها

### `user` — احراز هویت
لاگین/لاگ‌اوت، سشن امن (`session_regenerate_id` بعد از ورود)، هش رمز با `password_hash`، داشبورد کاربری. اگر کاربر جاری `admin`/`owner` باشد، در داشبورد کاربری‌اش لینک **«ورود به پنل مدیریت»** می‌بیند. ساخت خودکار حساب پیش‌فرض در نصب.

### `admin` — پنل مدیریت
داشبورد با آمار سیستم (کاربران، آیتم‌های منو، نسخه، حجم دیتابیس)، مدیریت کاربران (لیست، تغییر نقش، فعال/غیرفعال — فقط `owner`، با محافظ عدم تنزل/غیرفعال‌سازی خودش). ناوبری پنل از دیتابیس (ماژول menu) خوانده و با قالب **همبرگری سمت راست** رندر می‌شود.

### `menu` — مدیریت منوی پنل
CRUD کامل آیتم‌های منو: عنوان، آدرس، ترتیب (بالا/پایین)، فعال‌سازی، نقش‌های مجاز، آیکون SVG از مجموعه آماده + ایمپورت/همگام‌سازی از `menu.php` ماژول‌ها. دسترسی: `admin` و `owner`.

### `database` — مدیریت دیتابیس (فقط `owner`)
وضعیت اتصال SQLite، مسیر و حجم فایل فعال، نسخه SQLite، آمار جدول/ستون/ردیف به تفکیک جدول؛ **بکاپ** (دانلود/حذف/فهرست)، **بازگردانی** با بکاپ خودکار `pre_restore_*`، ساخت دیتابیس جدید و **تعویض دیتابیس فعال** (via `active.txt`). بعد از تعویض/بازگردانی، خروج امن و هدایت به لاگین.

### `pages` — سایت عمومی
صفحات وب‌سایت جدا از پنل: روت `/` (صفحه اصلی، **بدون نیاز به لاگین**)، `/page/{slug}`، مدیریت کامل در `admin/pages` (افزودن/ویرایش/حذف، انتشار/پیش‌نویس، تعیین صفحه اصلی). نامک (slug) یکتا و انگلیسی اعتبارسنجی می‌شود؛ صفحه پیش‌نویس publicly **۴۰۴** می‌دهد؛ اگر هیچ صفحه‌ای نباشد، صفحه خوش‌آمد پیش‌فرض ساخته می‌شود.

### `update` — به‌روزرسانی از گیت‌هاب (فقط `owner`)
بررسی نسخه جدید از ریلیزهای گیت‌هاب، نصب تک‌کلیکی با **بکاپ خودکار**، محافظت از `database/` و `config.php` (هرگز بازنویسی نمی‌شوند)، و ردشدن از کپی `install.php`.

## امنیت

- رمزها با `password_hash` (الگوریتم پیش‌فرض PHP) ذخیره می‌شوند؛ هرگز plain-text
- `session_regenerate_id(true)` بعد از لاگین و لاگ‌اوت (مقابله با session fixation)
- توکن **CSRF** در تمام فرم‌های POST پنل
- prepared statement در همه کوئری‌ها (PDO)
- نصب‌کننده بعد از نصب خودش را حذف می‌کند + گارد ۴۰۳ اجرای مجدد
- فایل‌های حساس (`database/*.sqlite`، `uploads/`، `backups/`) در `.gitignore` و خارج از ریپو

## ساخت ماژول جدید — راهنمای عملی

۱. پوشه `modules/blog/` بسازید.
۲. `routes.php`:
```php
$router->get('blog', 'blog', 'Controller', 'index');
$router->get('blog/{id}', 'blog', 'Controller', 'show');
$router->get('admin/blog', 'blog', 'Controller', 'manage'); // پنل
```
۳. `Controller.php` با namespace `Modules\blog`:
```php
namespace Modules\blog;
use Core\Controller as BaseController;

class Controller extends BaseController
{
    public function index(): void
    {
        $this->view('blog', 'index', ['posts' => (new Models\PostModel())->all()]);
    }
}
```
۴. `Models/PostModel.php` با متد `migrate()` برای ساخت جدول.
۵. `views/index.php` برای قالب.
۶. (اختیاری) `menu.php` برای آیتم منوی پنل — بعد در پنل روی «همگام‌سازی از ماژول‌ها» بزنید.

تمام — بدون ثبت‌نام در هیچ فایل مرکزی.

## دیپلوی و به‌روزرسانی

- **نصب اول:** فقط `install.php` (بخش نصب را ببینید)
- **به‌روزرسانی:** پنل → «به‌روزرسانی» → بررسی نسخه → نصب (بکاپ خودکار، بدون دست‌خوردن دیتابیس)
- **نسخه‌گذاری:** هر ریلیز نسخه بالاتر می‌گیرد؛ نسخه قبلی هرگز برای کد جدید استفاده مجدد نمی‌شود

## نسخه‌ها

- **۰٫۴٫۰** — ماژول pages (سایت عمومی: صفحه اصلی `/`، صفحات `/page/{slug}`، مدیریت در پنل)؛ قالب منوی **همبرگری سمت راست** برای پنل ادمین؛ آیتم «پنل کاربری» در منوی ادمین؛ لینک پنل مدیریت در داشبورد کاربری برای admin/owner؛ حذف لینک آپدیت از داشبورد کاربری؛ انتقال روت `/` از user به pages
- **۰٫۳٫۰** — ماژول menu (مدیریت آیتم‌های منوی ادمین از پنل: افزودن/ویرایش/حذف/ترتیب/فعال‌سازی/دسترسی نقش/آیکون؛ سایدبار از دیتابیس)
- **۰٫۲٫۰** — ماژول database (وضعیت اتصال، آمار، بکاپ و بازگردانی، ساخت و تعویض دیتابیس؛ فقط owner)
- **۰٫۱٫۱** — اصلاح عنوان جدول منو در داشبورد ادمین
- **۰٫۱٫۰** — ماژول admin (پنل مدیریت، منوی ماژولار، مدیریت کاربران)؛ رفع باگ آدرس‌های نسبی (ریدایرکت مطلق + تگ `<base>`)
- **۰٫۰٫۶** — رفع ۴۰۴ برای درخواست مستقیم `index.php`
- **۰٫۰٫۵** — رفع باگ نصب‌کننده (POST-Redirect-GET)؛ تغییر نام به `install.php`؛ محافظ نصب‌تکراری (۴۰۳)
- **۰٫۰٫۴** — تنها مسیر نصب، نصب‌کننده تک‌فایل است (حذف خودکار بعد از نصب)
- **۰٫۰٫۳** — نصب‌کننده تک‌فایل (دانلود خودکار آخرین ریلیز از گیت‌هاب)
- **۰٫۰٫۲** — نصاب خودکار + ماژول update از گیت‌هاب
- **۰٫۰٫۱** — هسته HMVC + ماژول user (لاگین، سشن امن، نقش‌های قابل‌توسعه)
